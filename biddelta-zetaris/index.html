Read the full narration

1. A tender changes after your team signs off. Which tasks need reopening, and which completed work should stay? BidDelta links each amendment to its affected tasks. This is a historical public tender with an illustrative supplier workspace.

2. One native Zetaris SQL query connects the historical notices, a REST task source, and a PostgreSQL document register. It returns eleven rows, seven evidence-to-task links, and five affected tasks. Each proposed action carries the exact source version. You can inspect the executed SQL and native response.

3. The financial clause adds minimum requirements; the technical clause adds questions. Existing turnover evidence and three case studies remain recorded. Both reviews share one request for the missing guidance, and final sign-off pauses until that guidance is reviewed.

4. Now a simulated colleague reopens the finance review and adds a note. The prepared plan still carries the earlier version. Checking that stale batch stops every write. Zero tasks change, and the colleague's complete note stays intact.

5. Refreshing runs another real Zetaris query. The reopened finance task is already aligned, so the new plan applies four changes and retains one. A final native query confirms the new source snapshot, with zero further writes. The completed architecture task and document records remain intact.

6. My experience building on Zetaris was practical: I installed the supplied platform, registered the sources, and tested the same query before and after a task changed. The useful moment was seeing the fresh task version arrive through the federation query alongside the original clause and document evidence. I also hit two concrete integration issues: local file access and a repeated-view query. Using the platform's PostgreSQL connector for the register and referencing each REST source once made this replay work. Zetaris is amazing here because one SQL result makes scattered evidence reviewable together. BidDelta then adds the version-checked task write-back. That separation gave me a clear, testable route from source evidence to a recorded decision while preserving the colleague's work.

7. The code, source provenance, and genuine execution receipts are public. For a supplier bid manager, the outcome is concrete: a changed tender becomes a fresh, reviewable task plan, with approved work preserved. Explore BidDelta by Blucca on GitHub.
