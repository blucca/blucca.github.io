1. Keep each result attached to its call

Vapi’s custom-tool response format associates each entry in results with a toolCallId. Our negative control returns the correct order data with a duplicated ID. The backend bodies and request counts pass; the exact output assertion fails.

In the response-building Code node, recover the corresponding source item through n8n’s item links:

const results = $input.all().map((item, index) => {
  const { toolCallId } =
    $('Split tool calls').itemMatching(index).json;

  if (item.json.statusCode === 503) {
    return { toolCallId,
      error: 'Order service temporarily unavailable. Please try again later.' };
  }
  // The full workflow also checks status and the orders shape.
  return { toolCallId,
    result: JSON.stringify({ orders: item.json.body.orders }) };
});
return [{ json: { results } }];

The complete importable workflow validates the tool-call input, carries the customer and call ID into the HTTP request, and maps each backend response back to its source item. Using .first() for every response produces the demonstrated regression.

Our fixture asserts the two IDs, their customer-specific data, and this workflow’s output order. Vapi also accepts correctly identified result entries in a different order; an ID-keyed comparison fits workflows that intentionally reorder results.

The HTTP Request node includes response status and uses Never Error, so response-building Code receives the returned 503. Customer A keeps its successful result; B receives an error string. An empty order list stays a successful result string.

Vapi’s documented envelope uses a single-line string for result or error. The supplied Respond to Webhook node is configured for HTTP 200. These recorded runs stop immediately before that response node; endpoint delivery is a separate live check.

Use your own export: the local case builder helps select the input/output boundary and download a Docker run pack. With an existing Node.js 24+ and n8n installation, the CLI is also on npm:
