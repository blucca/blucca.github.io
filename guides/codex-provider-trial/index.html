01 / Prepare a trial

A profile, not a migration.

Use the Codex you already have. Check codex --version: this recipe was run on CLI 0.163.0 and 0.171.0, using the NAME.config.toml sidecar format. The provider must support the Responses API.

    Keep the useful parts.
    I already use CC Switch or All API Hub.
    Keep using it. Current CC Switch already preserves unrelated config, and All API Hub exports into it. A native trial profile is useful when you want to test one provider without installing another manager or changing your live defaults.
    Older Codex versions use a different profile format.
    This recipe uses the native sidecar file format observed in CLI 0.163.0. Update an older npm installation with npm install -g @openai/codex, or use your existing package manager. Older [profiles.NAME] tables are a different configuration format.
    I corrected the model or base URL. How do I retry?
    Changing the form updates the generated text. A sidecar already saved on your computer keeps its original model and endpoint; both setup commands retain an existing same-name file.
    1. Return to the builder, enter the corrected base URL and model ID enabled for your token group, and choose an unused profile name, such as trial2. Click Build my commands.
    2. Copy the newly generated Profile + terminal-only key block and run it with the same CODEX_HOME. It creates the new sidecar and prompts for your key.
    3. Run the newly generated Model discovery and Native task / JSON events blocks. The task now launches the new profile, for example codex exec -p trial2. Keep its matching receipt pair.
    Your earlier profile stays available under its original name.
    The API lists models but the task fails.
    Check the exact model ID, token group and Responses support. The base URL is the API root before /responses. The profile uses provider-specific env_key authentication and HTTP streaming, so the key is available to Codex in the same terminal.
    What happens to existing settings?
    Codex loads the base configuration and layers this model/provider profile over it. For an already-trusted project, the native check preserves the full base file. In a new project, Codex may persist its normal trust entry. Leave MCP and trust entries in your base; the generated profile contains a complete provider table. Project-local settings can also affect the task. The trial creates a new CLI session; your normal launch uses the original defaults.
