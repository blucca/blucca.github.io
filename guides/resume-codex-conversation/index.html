1. Install once. Use your existing Codex.

First install and sign in to Codex CLI. In the shell you will use for Desk, run the Linux/macOS/WSL commands below. The release wheel installs without Git.

python3 --version
codex --version
mkdir -p "$HOME/codex-desk-install"
cd "$HOME/codex-desk-install"
python3 -m venv .venv
. .venv/bin/activate
python3 -m pip install https://github.com/blucca/codex-desk/releases/download/v0.1.0a13/codex_desk-0.1.0a13-py3-none-any.whl
codex-desk

Desk checks the selected launcher with --version before opening. If it fails, run the printed command in the same shell and repair that Codex installation. Open the printed local URL, normally http://127.0.0.1:8787. Windows PowerShell installation · 90-second illustrated walkthrough.

2. Find the saved title, then resume.

  1. Choose Open a project and enter the folder where the conversation started. Keep Current Codex settings for your first resume.
  2. Enter a word or phrase in Search conversation titles, then click Find existing sessions or press Enter.
  3. Resume the matching conversation. Read its previous messages and expand its command, file and MCP results before sending anything.

Not in the results?

Project search matches the exact saved working directory (cwd). A conversation started in /projects/my-app/api will not appear under /projects/my-app. Use that subfolder, or choose Browse existing Codex sessions in the sidebar to search across folders.

Search matches the native extracted title, not message text or tool output. Leave the title field blank to list that scope. After editing a query, submit it again; Load more continues the submitted query.

Prefer the terminal after finding the native thread ID? Use the same Codex home and saved folder:

cd /absolute/path/to/saved/project
codex resume <UUID>

Replace <UUID> with the saved thread ID. For a non-default home, set CODEX_HOME to that same path in this shell. Resume uses the CLI’s current settings and sign-in.

3. Complete one small task in your own project.

Choose Work — native tools and edits. Paste this next task and click Run task:

Find this project's verification command in README, run it, and report the exact command, output and exit status. Do not install dependencies or edit files.

Review any native command approval. Check the actual command output and exit status alongside the summary. Keep the result in this conversation for your next visit.

4. Return to the same conversation.

Close the browser, reopen Desk’s printed URL while its terminal is running, and choose the same named session. Closing the page leaves the backend running; Ctrl+C stops Desk and its owned native tasks.

Next time, launch without reinstalling:

cd "$HOME/codex-desk-install"
. .venv/bin/activate
codex-desk

Reuse the original --codex, --codex-home and --state-dir arguments if you supplied them. A saved, used conversation resumes its original native thread. A never-used blank conversation has no saved rollout yet.

Keep projects and next tasks organized.

Saved sessions are grouped by project, with active tasks kept visible. Use Find saved work to filter titles or folders, Archive to tuck away finished work, and Show archived to find and restore it. Archiving changes the local Desk list and keeps the conversation’s history and draft.

Write a next instruction and choose Save as follow-up instead of Run task. It stays in that conversation’s prepared list, tied to its project and provider, when you switch projects or restart Desk. Restart leaves follow-ups paused: review the conversation and choose Send next when it is idle. Each click sends one prepared task; the rest stay saved. Prepared follow-ups in the README.

Two accounts? Local history and current sign-in are different.

Desk browses the selected CODEX_HOME, normally ~/.codex. Switching personal/work sign-ins does not select a different local history folder. If both accounts used the same home, conversations can remain visible after the sign-in changes.

The saved modelProvider is history metadata, not a credential. A same-thread resume uses your selected current settings and their available authentication. Desk does not switch accounts for you.

If the conversation lives in another existing home, stop Desk and launch with its original path:

codex-desk --codex-home /absolute/path/to/your/codex-home

If saved history is missing, restore it or use the original home. Desk keeps the saved binding; choose Start new conversation explicitly for new work.

Choose Continue with another provider in an open session, or Review handoff beside a saved conversation. Review visible messages, command/file/MCP evidence, write the next goal, and select the target profile whose endpoint and model you verified.

Switch Codex API provider: save the target profile, review one next goal, and reopen the new conversation.

Native list/read fields behind the search

Field examples for an initialized app-server connection, pinned to Codex CLI 0.171.0’s thread protocol. Desk’s released list adapter uses:

{"id":1,"method":"thread/list","params":{"limit":30,"modelProviders":[],"sortKey":"updated_at","cwd":"/home/you/projects/my-app","searchTerm":"verification"}}
  • cwd is an exact path match; omit it for global browsing. searchTerm is a substring of the extracted title; Desk omits it for a blank query.
  • modelProviders: [] includes all recorded providers. Desk omits currentAccountOnly; its native default is false, so this local list is not restricted to the currently signed-in ChatGPT account.
  • Desk omits archived and sourceKinds: native defaults list non-archived, interactive history. Results arrive in result.data; repeat the same filters with cursor: result.nextCursor for the next page.

A metadata-only read uses the returned thread ID, as in Desk’s read-only backend inspector:

{"id":2,"method":"thread/read","params":{"threadId":"<id from result.data>","includeTurns":false}}

includeTurns: false reads metadata. Desk uses includeTurns: true when opening saved history or reviewing handoff evidence. Neither list nor read starts an inference turn.
