A parcel claim starts with photographs someone else can check. Capture Loop keeps the full label, asks for a useful closer view, and links a confirmed field to both originals. This is the working OpenCV five and AWS application.

Start the two-view sample. The agent calls the private AWS image tool, checks the document boundary and page focus, then opens field review. The small printed code has only eighty-seven by twenty-five source pixels. We keep that full-label context and request a closer detail.

First, a deliberate wrong-photo control. I upload a separate parcel as the detail. OpenCV finds too little corresponding print. The agent asks for another view with surrounding marks. The full label stays selected, and the next upload carries this request forward.

Now load the paired detail. OpenCV matches features, checks the target coverage, and maps the field into the new original. The agent opens a fresh review. The target now occupies one hundred seventy-one by forty-seven source pixels, about twice the linear sampling. This controlled pair comes from one licensed photograph.

Compare the two crops, enter the visible form code, and confirm the field. This reviewer entry is scripted. The saved review identifies both originals, both field crops, and the selected readability response. Export the session to inspect the measurements and the actual native tool calls.

Here is the architecture. Whole-label measurements run in private AWS Lambda. Field mapping runs in the station with OpenCV five. The model receives numerical observations and prior requests. Its next tool either requests a retake or opens review. Executable checks govern both actions, and people supply the field values.
